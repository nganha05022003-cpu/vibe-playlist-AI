01 — problem

mood is visual, not verbal

every music app starts with a search bar. but mood doesn't work that way — you can see a vibe in a rainy café window or a golden-hour rooftop, but you can't always translate that into keywords like "chill indie acoustic."

the gap: there's no way to go from a visual moment to a matching soundtrack without manually describing your feelings in words.

"I know the feeling I want, but I don't have the words for it — and the search bar doesn't understand vibes."

02 — insight

multimodal AI can bridge the gap

GPT-4o Vision can "see" an image and extract structured emotional data — mood, energy level, atmosphere, and even musical genre associations. this means an AI can do what humans struggle to do: translate a visual scene into a set of musical parameters.

the hypothesis: if I feed a photo to a vision model, it can generate search terms accurate enough to find matching music — without the user typing a single word.

03 — first solution

a streamlit web app with spotify

version 1 was a browser-based app: upload a photo → GPT-4o analyzes the mood → Spotify API creates a playlist in the user's account.

open browser → navigate to URL → upload photo → wait for AI → click "generate" → open spotify

it worked. but two critical problems emerged immediately.

04 — what I discovered

too much friction, and a platform wall

problem 1: friction. six steps from "I see a vibe" to "I hear matching music." every extra tap is a chance for the user to drop off. browser-based upload felt clunky compared to the immediacy of the mood itself.

problem 2: spotify's policy shift. in february 2026, Spotify changed their developer mode policy — all API access now requires the app owner to have Premium. this meant every user would face an authentication wall and subscription requirement.

spotify's platform risk materialized in real-time: a third-party dependency I had no control over changed the rules mid-build. this is exactly the kind of risk PMs need to evaluate when choosing external dependencies.

05 — pivot decision

from web app to agentic system

two simultaneous pivots, each driven by a different insight:

before

spotify API

requires premium, oauth flow, user login, subscription check

after

iTunes search API

free, no auth, no login, 30-second preview URLs included

before

streamlit web app

6 steps, browser-dependent, desktop-first experience

after

iPhone shortcut + fastAPI

1 tap, native camera, zero-friction mobile experience

the architecture shift was fundamental: instead of a web page that waits for user input at every step, I built an agentic pipeline — one trigger sets off a chain of autonomous AI decisions with zero additional user interaction.

📸 snap photo → 🤖 AI reads mood → 🎵 finds tracks → 🔔 notification
06 — final architecture

three interfaces, one brain

the final system has a single fastAPI backend that serves three different interfaces — each optimized for a different context:

07 — results & AI learnings

what I built, and what I learned

AI concepthow I encountered itPM takeaway
non-deterministic output GPT-4o returned different mood analysis for the same image across calls design for "good enough," not exact
prompt engineering small changes in system prompt dramatically changed JSON quality prompt design is a product skill
platform dependency risk spotify changed API policy mid-project, breaking core functionality evaluate platform risk as seriously as tech risk
latency as UX free-tier cold starts added 30–50s delay, causing shortcut timeouts infra cost directly impacts user experience

the most important learning: AI automates the how of execution more readily than the why. strategic framing — which problem to solve, which platform to build on, which trade-offs to accept — remained entirely human decisions throughout.

08 — what I'd do differently

next iteration

evaluate platform policies before building. I spent significant time integrating spotify before discovering their policy change. in a real product team, I would have validated API terms and access requirements in the first sprint.

start with mobile-first architecture. I began with a desktop web app and later pivoted to iPhone shortcut. if I started over, I would design the agentic mobile experience from day one.

add a feedback loop. currently the AI suggests tracks but the user can't tell the system "this doesn't match." a lightweight thumbs-up/thumbs-down mechanism would create a feedback signal for iterating on prompt quality — and demonstrate understanding of RLHF concepts.
